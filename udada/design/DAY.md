# 하루 한 장: 일정 · 할 일 · 식히기를 한 화면에

> 결론 먼저: **할 일 앱의 실패는 '목록'에서 온다.** 시각 없는 일은 23%만 끝나고(시각 있는 일은 50%), 시각을 박아도 78%는 늦게 끝난다.
> 그래서 목록도 시간표도 아닌 **세 띠(아침·낮·저녁)** 에 일을 놓는다. 약속만 시각을 갖고, 할 일은 띠 안에서 자유롭다. 늦어도 '밀림'이 아니다.
> 동작판: `day.html` · 판정: `node tests/day.test.js` → `day: 0 fail`
> VALUE.md(27편)·REFRESH.md의 근거는 그대로 쓰고 다시 적지 않는다.

## 1. 읽은 것 → 정한 것

## 2. 설계

**한 줄**: 하루를 세 띠로 나눈 한 장. 약속은 박히고, 할 일은 띠 안에서 떠 있고, 빈 틈은 숫자로 보인다.

- **넣기**: 아래 한 줄에 적는다. `3시 치과` → 일정, `보고서 30분` → 지금 띠의 할 일, `내일 저녁 빨래` → 내일 저녁. 칩(날·때·길이)은 고치고 싶을 때만. 엔터 한 번이 기본 경로.
- **보기**: 약속 = 꽉 찬 먹색 덩어리(못 움직임), 할 일 = 열린 줄(움직임), 지금 = 코발트 한 줄. 색이 아니라 **채움**이 성질을 말한다.
- **끝냄**: 네모 한 번. 줄이 그어지고 자리에 남는다(위치가 안 튄다). 지우기·비우기는 확인 창 대신 되돌리기.
- **고치기**: 줄을 누르면 아래 시트. 끌어 옮기기 없이 칩으로 날·띠·길이를 바꾼다.
- **식히기 / 하루 닫기 / 나중에 / 달력**: 각각 한 번 눌러 열리고, 안에서 고를 것은 셋 이하.

**디자인 방향**: 인쇄된 시간표. 띠 이름은 세로쓰기(부리 글꼴), 시각은 좁은 숫자체로 크게, 둥근 모서리·그림자·그라데이션·아이콘 없음. 색은 먹·바탕·코발트(지금)·박하(쉬기) 넷. 쉬는 화면만 밤색으로 뒤집힌다.

## 3. 판정 기준과 한계

- 검사: 4개 크기(360×640~440×956) + 키보드 + 어두운 화면에서 넘침·화면 밖·44px 미만 0, 전체 흐름(넣기→끝냄→옮기기→식히기→하루 닫기→나중에→달력), 한 줄 읽기 10가지.
- 쓰면서 볼 숫자: 넣은 일 중 끝낸 비율(기준선 49.5%), 버린 비율(32.0%), 넣는 데 걸린 시간.
- Halder 2026은 심사 전 프리프린트이고 관찰 연구다(시각을 박은 사람이 원래 다른 사람일 수 있다). 설계 시사점 절은 요약으로만 읽었다.
- Tonietto 두 편, Kruger & Evans, Fitz는 초록이 아니라 대학 보도자료·2차 요약으로 확인했다. Parhi 2006은 재확인 못 했다.
- 한 줄 읽기는 규칙 기반이다. `9시`는 지났으면 저녁 9시로 읽는다. 틀리면 미리보기 줄에서 바로 보인다.
- 아직 없는 것: 기기 달력 읽기, 알림, 반복 일정, 끌어 옮기기. 네이티브로 옮길 때 넣는다.
